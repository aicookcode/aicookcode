用 AI 写代码时，很多人都有过类似体验：你把需求一扔给 agent，它立刻开写，速度看起来很快，结果方向跑偏、需求漏掉，后期不得不花大量时间反复修改和拉扯，效率低还超级心累。问题往往不在于“AI 不够聪明”，而在于它缺少一套像成熟工程师那样的工作方法。

最近很火的开源框架 superpowers 解决的正是这个问题。它的思路很直接：不要让 AI 一上来就写代码，而是先像靠谱工程师那样，先调研、先提问、先思考、先规划，确认无误后再执行。

superpowers 到底是什么？

superpowers 是由Jesse Vincent开发的一个开源框架，兼容Claude、Cursor、Codex、Gemini CLI 等主流 AI 编码环境。它内置了 14 项核心 skills，会根据任务自动触发，并强制 agent 按照更结构化的方式完成工作。和“写一个更强的 Prompt”不同，superpowers 更像是在 AI 外面套上了一层工程化流程，让它从“会写”变成“会做项目”。截至目前，superpowers 已经在 GitHub 上拿到了超过137k star，热度非常夸张。

superpowers 最有意思的地方：让 AI 先想，再干superpowers 把一个开发任务拆成了7个阶段。简单任务不需要走完全部流程，但面对多文件协作、功能开发、复杂改动时，这套分阶段机制能显著降低“AI 看起来在做事，其实越做越偏”的情况。

step 1. 头脑风暴：先别写，先把事想明白这是 superpowers 最常用、也最关键的一步。新任务开始时，它不会立刻进入写代码模式，而是先去查看项目文件、文档和最近改动，然后通过一系列受控动作把需求摸清楚：

- 一次只问一个问题，避免信息轰炸
- 给出 2-3 个方案，并附带优缺点和推荐
- 分模块展示设计，逐步确认
- 生成设计文档，并主动检查漏洞
- 必须等到你明确批准后，才会进入下一阶段

先确认边界、对齐目标，把那些后期最容易扯皮的问题提前聊清楚。

step 2. 规划：把执行步骤写到不能含糊当头脑风暴通过后，superpowers 会生成一份详细计划，包括依赖关系、验收标准、涉及文件以及执行顺序。这里有个有趣的铁律：不允许出现 TBD、TODO 等任何占位符。也就是说，每个子任务都必须定义清楚，清楚到即使执行者完全不熟悉代码库，也知道下一步该做什么。

step 3. 子代理并行：主 agent 不亲自下场埋头写进入实际开发时，superpowers 的思路也很“工程化”。主 agent 不会自己包揽所有实现，而是把任务拆分给多个子代理并行处理。每个子代理有各自独立的上下文，主 agent 负责的是分配任务、审查结果和盯进度。面对多文件改动、模块联动、复杂功能时，这种模式的效率优势会非常明显。

step 4. TDD：先写失败测试，再写代码superpowers 对测试的要求也非常严格。它坚持测试驱动开发的基本顺序：先写一个会失败的测试，再写最小可通过的实现，然后再重构。如果某段生产代码没有经过测试验证，它甚至会被直接删除。这种做法听起来有点“强硬”，但也正是这种强硬，让它更像工程流程，而不是“先跑起来再说”。

step 5. 双重代码审查：不是写完就算结束代码完成后，superpowers 还会安排两次独立审查：

- 一次检查实现是否符合最初计划
- 一次检查代码本身的质量

而且这两次审查会交给不同代理完成，避免彼此影响。双重代码审查解决了两个关键问题：第一，做的是不是原来要做的事；第二，做出来的东西质量到底行不行。

step 6. 系统性调试：修 Bug 也不能乱来遇到 Bug 时，superpowers 不是简单粗暴地反复试错，而是按固定路径处理：重现问题 → 找到根本原因 → 只做一个假设 → 最小改动 → 验证结果。superpowers 还设置了“三次打击规则”：如果连续三次修复失败，就不允许继续修改，而是必须停下来重新审视设计或架构。

step 7. 收尾工作：把最后一公里也纳入流程任务完成之后，superpowers 还会继续处理后续动作，比如分支合并、PR 创建、现场清理等。这意味着它关注的不只是“代码写完没有”，而是整个任务有没有被完整交付。

superpowers 适合什么场景？

superpowers 最适合的是这几类任务：

- 多文件联动的功能开发
- 涉及设计、实现、测试、审查的完整需求
- 需要多人协作思维的复杂任务
- 需要降低返工率、提高稳定性的项目型工作

如果只是改一个颜色、修一个拼写、替换一段文案，这种级别的小任务，用它反而可能有点“大材小用”。另外，它前期的头脑风暴和规划阶段会消耗更多上下文 token。做大项目时，这一点也需要纳入成本考虑。

superpowers 为什么会这么火？

短短几个月，superpowers 就冲到了137k star，成为 GitHub 热门趋势项目。这说明很多开发者已经意识到：光靠更好的 Prompt 还不够，AI 真正需要的是一套结构化的工作方法。

superpowers 把优秀工程师的开发习惯，变成了 AI 也能一步步执行的框架，让 AI 写代码从“乱拳出击”逐渐变成“有章可循”。
