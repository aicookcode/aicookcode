我已经让我的 Muse Agent，自己去参加比赛挣奖金了。

账号是它自己注册的，题是它自己做的，代码是它自己写的，最后也是它自己提交的。

我全程主要负责两件事：**动嘴、点头。**

## 先说参赛平台

这个平台叫 **make.fun**，是一个直接面向 AI 编程 Agent 的赏金比赛平台。

![make.fun 赏金比赛首页，展示 Markdown 渲染提速任务、250 美元奖金和实时排名](/media/makefun-agent-bounty/bounty-platform.png)

出题方把编程任务挂出来，全球的 Agent 来做题、交作品，平台按规则评分排名，前几名按名次分钱。人在这里只当幕后的「老板」：选题、批准、最后领奖。

也正因为下场的不是人，规则和普通编程比赛完全不同——评分靠机器或明确规则，还必须交出完整的 AI 构建过程记录，防止有人拿人类写的代码冒充。

先说明一下：能干这活的不止 Muse。make.fun 不挑 Agent——Claude Code、Codex，或者其他能留下完整会话记录的 Agent，都可以参加。我手边用的是 Muse，所以下面全程出镜的就是它。

> 顺带安利一句：Muse 给新用户赠送的免费额度是真的香，它还有一台自己独立的电脑运行环境，能真正动手干活——就拿这次比赛来说，任务完成得相当不错。大家可以注册去试一试。
>

## 演示一下：我其实只说了两句话

整个启动过程，没有想象中那么复杂。

**第一句话**——注册平台：

> Help me create an account on https://make.fun/r/rcs0dd9w to take on bounty tasks, and install its skill

就这一句，它自己完成了三件事：读懂 make.fun 的官方指南、装好官方 Skill、在本地生成一个 Solana 密钥对。

<small>提示：在 make.fun 上，这个密钥对本身就是账号，也是收款钱包。账号名由平台自动生成。</small>

然后它把当时开放的十几道题列给我看：奖金多少、什么时候截止、怎么评分、有没有报名费之类的前置条件。

![Muse 列出三项赏金任务，作者选中 Markdown 渲染提速任务](/media/makefun-agent-bounty/task-selection.png)

我回了**第二句话**——选择任务：

> 先做 markdown-render-speed-02 — $250，今天下午 3:30 截止

选它的原因很简单：Muse 给出的评估，这个任务不需要任何前置条件，不需要报名费，可以直接开干。唯一的缺点是截止时间紧，那就更考验 Agent 了。

接下来就是它干活，我围观：开启录制、从零写代码、用 720 个测试用例逐个对拍、本地跑官方评分……

最后结果：**720/720 全部逐字节一致，速度比 marked 快约 1.4–1.5 倍**，正式提交成功，平台的各项检查也都通过了。

![Muse 确认作品提交成功，并汇总 720 项测试通过和运行速度结果](/media/makefun-agent-bounty/submission-success.png)

两句话，注册、选题、开发、提交，全齐了。

## 一个问题：Agent 的账号，我登不上去

提交完之后，尴尬的事情来了。

Muse 自己注册的那个账号，是靠本地的私钥在工作的。私钥不能外传、更不能拿来在网页上随便登录——也就是说，**这个账号它能用，我用不了。**

解决办法是平台早就留好的：我自己注册一个个人账号，再把 Agent 的账号关联（合并）过来。

### 第一步：注册个人账号

很简单：打开 make.fun，用 GitHub 一键登录。

### 第二步：关联合并账号

然后给 Agent 发这句提示词，就可以直接照抄：

> 注册好了，请把你自己注册的 Agent 账号合并到我的个人账号下，生成合并链接和验证码发给我，我来批准。注意：合并会吊销旧的 API key，所以要等作品提交完成后再合并。

Agent  会生成一个 **15 分钟有效的链接和一串验证码。**

![Muse 发来有效期为 15 分钟的账号关联链接，并提示核对验证码](/media/makefun-agent-bounty/account-connect-link.png)

在登录着个人号的浏览器中点开链接，核对验证码一致，点批准——合并就完成了。

![make.fun 账号关联页面，标出核对验证码的位置和批准按钮](/media/makefun-agent-bounty/account-connect-approval.png)

合并后，Agent 账号名下的参赛记录、将来的奖金，全部转到我的个人号名下；原来那个钱包也不会消失，它会留作个人号下面的 Agent 收款钱包。Agent 的旧 API key 会被吊销，平台会给它换一把新的，不影响它继续干活。

这里提醒一句顺序：**关联别抢跑——等正在执行的任务全部跑完、作品提交完成，再做关联**。因为合并会当场吊销旧的 API key，任务没跑完就合并，正在进行的提交流程可能被直接打断。

如果你是从零开始，其实更推荐反过来的顺序：先自己注册个人号，再让 Agent 生成关联链接关联到你名下，从第一天起记录和奖金就都归你，省掉事后合并这一步。

## 注意事项：最重要的是一条「全程录像」规则

这个平台最硬的规矩，叫 **transcript（会话记录）**。

说白了，就是 Agent 写代码的全过程录像的文字版：你最初的任务原话、Agent 每一步的操作、代码是怎么一行行写出来的、每条消息的 token 用量，全部要随作品一起提交。平台会拿记录去对代码——代码里的东西，必须能在记录里找到出处。

由此带来几条实操注意事项：

1. **先开录制，再写代码**。录制开始之前写的代码不算数，漏了这一步，等于白干——从 2026 年 11 月 17 日起，没有完整 transcript 的作品会直接拒收。好在这一步不用你操心具体怎么录：**开工前提前跟 Agent 交代一句就行，录制它会自己处理**。
2. **构建的对话里只聊任务**。闲聊也会进记录。有什么疑问，另开一个对话问——我这次就是这么干的，讨论和吐槽都在另一个对话里，构建对话干干净净。
3. **私钥永远不要发到聊天里**。它只存在 Agent 本地，任何人、任何平台管你要，都不要给。

## 现在战况如何：排名动态变化，正在连夜优化

说回我这场比赛——只要比赛还没结束，排名就一直在变。

第一轮作品提交后，我只排在 **第 119 名**。是因为第一版只保住了质量，没来得及拼速度，而奖励线卡在前 20 名，差距有点大。

于是我让 Muse 继续优化：质量一分不让，只往下压速度。几轮迭代下来，按本地测算已经挤进了前 20——但还不能松懈，对手也在交新版本，截止前排名随时可能再变。不得不说，只要一参与竞赛，人就忍不住热血沸腾。

再过几个小时，这道题就要截止了，我们会在结束前提交最后一个最优版本。最终名次要用截止后新抽的决赛题集重新评，**12 月 1 日公布结果**。到时候是真赚到了，还是陪跑一趟，我会发续篇，如实汇报——赚了报喜，陪跑就当交学费复盘。

## 写在最后

以前我们说「让 AI 帮我干活」，大多还停留在写写文档、改改代码。

这次不太一样：它自己注册账号、自己参赛、自己冲排名，奖金直接走链上结算——**Agent 经济这个词，第一次有了可以亲手摸到的样子。**

门槛其实不高：你需要一个能干活的 Agent，和两句说清楚目标的话。剩下的，它比你想象中更能干。
