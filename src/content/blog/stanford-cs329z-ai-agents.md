## 01｜为什么说这门课值得关注？

现在做一个 AI Agent，似乎越来越简单。借助 LangChain、LangGraph 等框架，给大模型接入几个工具，配置好提示词，就能让它搜索网页、查询数据库，甚至自动执行任务。

但真正把 Agent 用到实际工作中，你会发现问题远没有这么简单。比如，让 AI 帮你整理一份项目报告，它可能第一次完成得很好，第二次却漏掉重要信息；执行到一半工具调用失败，也不知道该如何恢复。

还有一些 Agent，表面上看起来能自己思考、自己规划，但任务一复杂，就会反复调用工具，既浪费 Token，又得不到正确结果。

**能让 AI 做事，和让 AI 稳定、可靠地把事情做好，是两回事。** 这正是 CS329Z 想要解决的问题。

课程并不局限于教某一种 Agent 框架，而是从底层原理开始，逐步讲解任务拆分、工具调用、记忆管理、多智能体协作、性能优化以及系统评估。

最终的目标，是让学生能够独立设计、构建和评估一个完整的 Agent 系统。

## 02｜从零开始，系统学习 AI Agent

课程的内容覆盖了当前 AI Agent 开发中的很多核心技术，但学习过程并不是简单地堆砌概念，而是从最基础的 Agent 组成讲起，再逐步深入到实际工程问题。

![CS329Z 课程内容总览：RAG、工具调用、Agent 记忆、多智能体、优化与评估等主题](/media/stanford-cs329z-ai-agents/course-overview.png)

### 第一部分：让 AI 学会查资料、使用工具

最开始，你会接触到 **RAG（检索增强生成）**。简单来说，就是让 AI 在回答问题前，先从指定的资料库中寻找相关内容，而不是完全依赖模型自身的知识。

例如，搭建一个公司内部的 AI 助手，让它能够查询企业文档、查找项目资料，再根据检索到的信息回答问题。

接着是 **Tool Calling（工具调用）**。如果说 RAG 让 AI 学会查资料，那么 Tool Calling 就是让 AI 学会使用工具。

查询天气、操作日历、运行代码、调用业务接口，都属于这个范畴。课程还涵盖了 **MCP** 等工具连接方式。

### 第二部分：让 Agent 能完成复杂任务

当 AI 有了工具，下一步就是解决怎样让它合理地使用这些工具。课程会介绍 **ReAct 等 Agent 设计模式**，以及 **LangGraph、DSPy 等开发框架**。

比如，你希望 AI 自动完成一份行业调研。它需要先规划任务，再搜索资料、筛选信息、整理结果，最后生成报告。如果中间某个步骤失败，还需要判断是否重试或调整方案。

这就涉及工作流设计、状态管理、上下文管理和 Agent 执行循环。课程还专门讲了 **Agent 的记忆机制**，以及**多个 Agent 怎样分工协作**。

不过，多 Agent 并不是越多越好。什么时候适合单 Agent，什么时候需要多个 Agent，如何避免它们互相等待、重复工作，也是课程讨论的重点。

### 第三部分：让 Agent 更聪明、更稳定

这部分开始进入更深入的**工程实践**，包括**优化提示词和上下文、选择合适的数据、降低错误率，以及判断是否值得进行模型微调**。

而且，课程还关注一个经常被忽略的问题：**Agent 做出来之后，怎样证明它真的有用？**

## 03｜最值得学习的，其实是 Agent 评估

我觉得这门课程非常有价值的一点，就是把 **Agent 评估**放到了很重要的位置。现在很多 AI 项目的演示看起来都很惊艳，但往往只是展示了一个成功案例。

真正上线后，它能不能稳定完成任务？复杂问题的成功率怎么样？失败后能不能恢复？这些问题，光看一段演示视频是无法回答的。

CS329Z 专门安排了 **Agent Evaluation（智能体评估）** 相关内容，教学生如何构建测试任务、制定评分标准，以及分析 Agent 的失败原因。

例如，让一个 Agent 自动处理 100 个不同的任务。我们不能只看它最后有没有输出结果，还需要判断结果是否正确、工具有没有用错、任务是否真正完成。

课程介绍的评估方法包括**自动化代码评分、LLM-as-Judge（让大模型辅助评判结果），以及针对多次执行结果的一致性分析**。

这对实际开发尤其重要。**一个真正好用的 Agent，不应该只是在演示时表现出色，而应该在不同情况下都能提供可预期的结果。**

## 04｜不只是听课，还有两套真正的实战作业

如果只是讲理论，这门课可能还没有那么吸引人。它还安排了两套完整的实践作业，而且已经在 GitHub 上公开了起始代码。

### 作业一：从零构建一个 Agent

第一套作业叫 *Building an Agent Harness*。学生需要从最基础的大模型调用开始，不依赖现成的 Agent 框架，自己构建一个企业内部 AI 助手。

它最初只能检索和分析企业邮件资料，随后逐步获得调用工具、执行终端命令、管理记忆，以及请求人工介入的能力。

这个过程很有意义。因为直接使用成熟框架虽然方便，却容易让人忽略 Agent 内部到底发生了什么，而从零实现一遍，就更容易理解模型、工具、状态、记忆是如何连接起来的。

GitHub 地址：

[https://github.com/cs329z/assignment1-harness](https://github.com/cs329z/assignment1-harness)

### 作业二：为 Agent 建立一套评估体系

第二套作业叫 *Building an Evaluation Task*。这一次，重点不再是继续给 Agent 添加新功能，而是检验它能不能可靠地完成任务。

学生需要设计测试环境、构建评估任务、编写评分规则，并分析 Agent 失败的原因。这也是很多实际 AI 项目从 Demo 走向产品时，必须补上的一课。

GitHub 地址：

[https://github.com/cs329z/assignment2-evals](https://github.com/cs329z/assignment2-evals)

除了这两套作业，课程还提供了 LangGraph、DSPy 等框架的课堂演示代码。如果你正在学习 Agent 开发，这些资料很适合拿来研究和练习。

## 05｜普通人应该怎么学习这门课？

看到斯坦福课程，可能有人会担心：是不是需要很强的数学基础，或者必须有多年 AI 开发经验？

实际上，这门课本身有一定技术门槛，主要面向具备编程和自然语言处理基础的学习者，但这不意味着普通人完全看不懂。

**如果你只是对 AI Agent 感兴趣**，建议先看第一讲：**What Are Agentic Systems?（什么是智能体系统？）**

这一讲会介绍 Agent 到底是什么、它由哪些部分组成，以及它和普通大模型应用有什么区别。即使暂时不写代码，也能借此建立一个比较完整的认识。

**如果你已经有 Python 基础**，或者正在学习 LangChain、LangGraph，可以重点关注 RAG、工具调用、Agent 设计模式和记忆管理这几部分。

**如果你已经开发过 Agent**，建议把更多时间放在评估、优化、安全机制和实战作业上。这些内容更接近真实项目需要解决的问题。

目前公开页面提供了部分课程视频、PPT 和推荐论文，能直接点击学习。部分课堂录像可能需要斯坦福 Canvas 权限，并不是所有课程内容都可以在外部直接观看。

好消息是，已经公开的课件和 GitHub 代码无需缴纳斯坦福课程学费即可访问。不过，运行实战项目时可能需要自己的模型 API Key，产生一定的调用费用。

## 06｜AI Agent 真正的门槛，正在发生变化

过去，学习 AI Agent，很多人的第一目标是让大模型调用工具，完成一些自动化任务。但随着各种 Agent 框架越来越成熟，搭建一个简单 Agent 的难度已经明显降低。

真正需要花时间解决的，是**如何让系统长期稳定运行、处理异常、控制成本，并且能够衡量效果**。这也是为什么我觉得 CS329Z 值得关注。

它没有把重点放在某个热门框架上，而是试图教会学习者**一套更完整的 Agent 工程方法**。

对于正在学习 AI 的开发者来说，这门课程可以帮助你补齐从原型到实际应用之间的知识。对于普通 AI 爱好者来说，也能借此了解：一个真正能帮人工作的 AI 助手，背后究竟需要哪些能力。

> **AI Agent 的未来，不只是让模型能够自动执行任务，更重要的是让它完成的每一项任务，都值得信任。**
