大家好，我是你的AI效率助手。今天我们来聊聊最近AI圈里热门的“Loop”（循环）概念。

很多人每天用 ChatGPT 或 Claude，但还是最慢的方式：打一个问题，等回复，修改，再问。效率很难上去，因为一直是你在推着 AI 往前走。

**Loop的核心精髓**：给AI一个明确的目标、验证标准和停止条件，让它自己迭代、检查、改进，直到达成目标，而你不用每步都盯着。

![](/media/agent-loop-guide/img_01.png)

## 1. 什么是Loop？和普通Prompt的区别

- **普通Prompt**：一次指令，AI给一个答案，然后等你决定下一步。
- **Loop**：一个递归目标。AI自己规划 → 执行 → 验证结果 → 发现问题 → 改进 → 重复，直到成功或达到上限。

## 2. Loop的三个关键部件

记住这三个就够了

![](/media/agent-loop-guide/img_02.png)

- **目标（Goal）**：清楚定义你要什么。

> 举个🌰
> “帮我制定一个适合上班族的30天早起习惯养成计划” —— 越具体越好。

- **验证（Verify）**：设定可检查的标准。这是Loop的核心，没有验证就容易自我欺骗。

> 例如：必须包含具体作息时间表，至少列出 3 个常见障碍和应对方法，并提供每日追踪方式。检查这些项目是否齐全后，再判断计划是否现实可执行。

- **停止条件（Stop）**：达到所有成功标准，或最多迭代4次。

额外加分（可选但推荐）：

- **保留状态（State）** —— 让AI记住上一轮哪里做得不好，避免反复犯同样的错误。

> 举个🌰
> 每次让AI在输出结尾加一句“状态总结”（比如：上一版起床时间太早，不够现实）。下一轮把这句话复制粘贴到新Prompt的最前面，AI就会参考它继续改进。这样循环效率更高、更聪明。

## 3. 大部分普通人真的需要完整Loop吗？

不需要！完整Loop（尤其是带自动化、子代理、代码环境的）适合开发者或高频重复任务，大部分人用反而可能增加复杂度和成本。

### 普通人适合的场景

（每周至少重复一次的任务）：

- 内容创作（文章、朋友圈、计划）
- 学习总结、知识提炼
- 日常规划（旅行、健身、购物清单）
- 问题解决（调试思路、决策分析）

如果任务是一次性的、质量高度主观（纯创意品味），或AI无法端到端完成，就用普通Prompt就好。![](/media/agent-loop-guide/img_03.png)

## 4. 适合普通人的“轻量Loop”方案（零代码，马上可用）

在**Claude、ChatGPT、Grok等任意大模型**里，直接用一个结构化Prompt就能模拟Loop。

![](/media/agent-loop-guide/img_04.png)

### 推荐万能Prompt模板

（复制粘贴改目标即可）：

```
你现在是一个高效的AI助手，我给你一个任务。请严格按照以下循环流程工作，直到完成或达到最大次数：

**任务目标**： [在这里写清楚目标，例如：帮我制定一个适合上班族的30天早起习惯养成计划]

**成功标准**（必须全部满足才算完成）：
1. ...
2. ...
3. ...

**工作流程**（每一步都必须执行）：
1. 第一次生成初始版本。
2. 严格对照成功标准打分（1-10分），列出不足之处。
3. 针对不足改进，生成新版本。
4. 重复以上，直到所有标准达到8分以上，或最多迭代4次。
5. 最后输出最终版本 + 改进总结。

开始执行吧，先输出第1版。
```

### 使用技巧

- 把Prompt一次性发完，让AI自己跑多轮。
- 对于复杂任务，可以分阶段：先让它生成大纲Loop，再针对每个部分Loop。
- 跟踪状态：下一轮对话时，附上“上一次的不足是XXX，继续改进”。
- 控制成本：设置最大迭代次数，避免Token爆炸。

### 完整示例：把会议记录变成可核对的待办

比起让 AI 自己评价“质量达到 8 分”，更可靠的起点是准备一份你能手工检查的小样例。下面是虚构的会议记录，用于演示验收方法，不是一次真实业务会议或模型效果测试。

```text
输入记录：
小林周五前整理接口清单；小周负责检查登录错误，但还没确定截止时间。
会上讨论过重做首页，没有决定是否执行，也没有指定负责人。

任务：仅提取已明确分配的待办，输出“任务、负责人、截止时间、原文依据”四列。

验收标准：
1. 恰好两条待办；未决定的首页重做不得列入。
2. 整理接口清单归小林，截止时间原样保留为“周五前”。
3. 检查登录错误归小周，截止时间写“未确定”，不能编造日期。
4. 每条待办都附上输入中的原文依据。

循环：先输出，再逐项检查这四条标准；不通过时说明哪项失败并修改。
最多修改两轮。仍有歧义时列出需要我确认的问题，然后停止。
```

手工核对时，结果应只有“小林—整理接口清单—周五前”和“小周—检查登录错误—未确定”两条。保留“周五前”的原文，是因为输入没有会议日期，不能凭空换算成某个日历日期。如果结果包含“重做首页”，就算表格排版再整齐也没有通过验收。

可以再增加一个反例：把输入改成“只讨论方案，没有分配任务”，此时应输出没有明确待办，而不是为了填表编造任务。用正例和反例检查输出，比模型自行打分更容易发现问题。

### 什么时候停止，什么时候交给人

| 情况 | 下一步 |
| --- | --- |
| 所有可核对的标准都通过 | 输出结果与检查记录，停止循环 |
| 缺少资料或输入自相矛盾 | 列出缺口，等待补充，不靠猜测继续 |
| 连续两轮重复同一错误 | 保留失败样例，交给人检查目标或方法 |
| 达到轮数、时间或费用上限 | 输出当前结果、未通过项和已用预算 |
| 涉及发消息、付款或改动线上数据 | 在真正执行前确认授权范围 |

在普通聊天中要求模型“循环”，只是在当前对话里组织多轮检查，并不自动获得后台定时运行、文件访问或外部工具权限。需要持续运行时，还要有真实的执行环境、状态记录和中断机制。模型的自查也不是独立证据：能用原文、人工答案或程序检查的部分，应优先用这些方法验证。

## 5. 日常实用小Loop例子

- **内容创作Loop**：目标“生成吸引人的标题+正文+结尾呼吁”，验证“点击欲强、通俗、有数据或故事”。
- **学习Loop**：目标“把这篇长文提炼成3个关键点+行动清单”，验证“是否覆盖核心、容易记住”。
- **健身/习惯Loop**：目标“根据我的目标制定一周计划”，验证“是否现实、可追踪、有备选”。

## 6. 进阶小Tips（可选学习）

- **拆分子任务**：大目标拆成小Loop，效果更好。
- **角色分离**：让AI先当“创作者”生成，再切换“严格审稿人”检查（同一个对话里说“现在切换到审稿模式”）。
- **手动触发**：不需要自动化，每天固定时间跑一个Loop就好（例如早上规划一天）。
- **观察迭代**：多看AI怎么自我纠正，你也能学到更好的思考方式。
