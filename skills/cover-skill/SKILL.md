# 博客封面提示词规则

本 skill 只负责为博客文章制定封面视觉方案和可直接复制的生成提示词。除非用户明确要求生成、替换或保存图片，否则不要修改项目资源，也不要擅自生成图片文件。

## 什么时候使用

当用户提出以下需求时使用：

- 为博客文章生成封面提示词；
- 根据文章标题或正文设计封面视觉；
- 让新封面符合当前网站风格、卡片比例或裁切方式；
- 为同一篇文章提供几套风格、构图或配色方案。

不要把它用于微信公众号专用封面、演示文稿封面或普通插图，除非用户明确要求沿用博客封面规则。

## 先确认版式，再写提示词

生成提示词前，先查看当前项目的文章卡片、首页精选卡片和全局样式，确认实际展示比例、裁切方式和主题风格。不要只根据图片文件的原始尺寸猜测比例。

当前项目的关键约束是：

- 文章列表卡片 `.post-cover` 使用约 `1.82:1` 的可视比例；
- 首页精选区域也是横向大图，但会在不同屏幕宽度下裁切；
- `PostCard` 中的 `width="800" height="500"` 不是生成比例，CSS 的 `aspect-ratio` 才是实际展示依据；
- 默认建议生成 `1820×1000 px`，或使用同等的 `1.82:1` 比例；生成器只支持常见比例时可退回 `16:9`；
- 主体、标题安全区和关键细节距离四周至少 8%—10%，避免在卡片裁切和移动端缩略图中丢失；
- 如果需要兼容首页精选卡片，优先使用横向构图，主体不要贴边，左右都保留可裁切的呼吸空间。

如果网站样式后来发生变化，以代码中最新的卡片比例和布局为准，并在输出中说明采用的比例。

## 从文章内容提炼视觉

先从文章标题、摘要和正文中提炼以下信息：

1. 一个核心主题或动作，例如“商品图变成短视频”“部署链路”“模型做判断”；
2. 一个主要视觉主体，例如手机、商品、编辑器、流程卡片或人物；
3. 最多两到四个辅助元素，用来说明上下文，不要把整篇文章的所有功能都塞进封面；
4. 文章的气质：实用教程、工具测评、项目复盘、观点文章或轻松分享。

用一个清楚的视觉隐喻组织画面。封面在缩小成文章卡片后仍应能一眼看出主题，不要用通用的“代码、芯片、发光网格”代替文章的真实内容。

## 网站风格基线

当前网站的封面应保持这些结构特征，但不限制为单一画风或颜色：

- 横向、主体明确、缩略图可读；
- 有编辑部或杂志封面的秩序感，画面干净，层次清楚；
- 可以使用轻 3D、精致插画、摄影拼贴或抽象图形，按文章主题选择；
- 适度使用圆角卡片、柔和阴影、纸张或细腻材质，让画面与网站的圆角卡片和留白相呼应；
- 避免过密的仪表盘、无意义的代码墙和大量装饰性光效；
- 默认不把文字画进图片。若用户要求封面含标题，保留明确安全区，并在提示词中逐字写出标题。

不要把“符合网站风格”理解成每篇都使用科技绿、青蓝或深色赛博朋克。配色应该服务文章内容，并与近期封面形成变化。

## 配色选择规则

如果用户没有指定颜色，至少给出三套可选配色方向：一套作为推荐，一到两套作为替代。配色名称要描述情绪和使用场景，不要只列色值。

- 推荐方向应与文章主题最匹配，而不是默认使用绿色或蓝色；
- 可用暖米白、杏橙、珊瑚、砖红、焦糖、芥末黄、酒红、紫灰、炭黑等方向，也可以根据主题使用其它色彩；
- 色值只是参考，不是硬编码要求。提示词中应强调色彩关系、明度和气质，而不是强行锁死一组 HEX；
- 同一篇文章的多个方案应有明显差异，例如“暖杂志感 / 深色高级感 / 明快活泼”，而不是只把绿色换成蓝色；
- 如果当前目录已有多张同色系封面，优先推荐不同色相或不同明度的方案，避免首页连续重复；
- 只有当主题本身需要时才使用霓虹、荧光或高饱和科技色，并明确控制光效和面积。

需要具体配色灵感时，读取 [references/palette-options.md](references/palette-options.md)，只选与文章气质相关的方向，不要把整份列表原样塞进最终提示词。

## 提示词编写规则

主提示词应按以下顺序组织，便于不同图像模型理解：

1. 使用场景、画幅比例和目标尺寸；
2. 视觉风格与整体质感；
3. 主体、动作或核心隐喻；
4. 辅助元素和空间关系；
5. 配色方向与光线；
6. 构图、留白、安全区和缩略图可读性；
7. 品质要求与不应出现的内容。

提示词要写成完整、可复制的自然语言。用户指定了 Midjourney、Flux、Imagen 或其它模型时，再按该模型支持的格式补充参数；不要凭空加入不确定或不兼容的命令参数。

负面提示词应动态生成：

- 总是排除低清晰度、模糊、畸形主体、杂乱构图、水印和未知品牌 Logo；
- 是否排除“科技绿蓝、霓虹、赛博朋克”等，要根据用户选择的配色和文章主题决定，不要把它们写成所有文章的固定禁用项；
- 用户要求封面含文字时，不要把“所有文字”列为负面项，而是排除乱码、错别字、额外文字和错误 Logo。

## 默认输出格式

除非用户要求更短的结果，否则按以下结构回答：

### 构图方向

用一两句话说明文章的核心视觉隐喻、主体位置和裁切安全区。

### 尺寸与裁切

写明比例、推荐像素尺寸、主体安全区，以及是否需要兼容首页精选区域。

### 配色选项

给出 3 套左右的方向：标注“推荐”和“备选”，说明每套的情绪、适合原因和主要色彩关系。颜色可变，不要把某一套写成唯一正确答案。

### 主提示词

给出一段可直接复制到图像生成工具的提示词。默认使用中文；只有用户指定英文或某个模型更适合英文时才改用英文。

### 负面提示词

给出与本次配色和构图相匹配的动态负面提示词。

### 生成备注

补充是否建议后期加标题、标题安全区、模型参数或多轮生成建议。不要把可选建议写成强制要求。

## 文案与文字处理

封面默认不嵌入标题，避免生成模型产生乱码，也方便同一张图在文章列表和首页精选区域复用。如果用户明确要求加入文字：

- 原样保留用户给出的标题，不擅自改写；
- 控制在一到两行，指定文字位置、字重、对比度和安全区；
- 只允许出现用户要求的文字，排除随机字母、伪 Logo 和额外标签；
- 说明“如果模型文字不稳定，可先生成无字底图，再后期叠加标题”。

## 完成前检查

提交提示词前确认：

- 已使用当前网站实际比例，而不是图片文件或 HTML 属性的偶然尺寸；
- 主题能从主视觉中被快速识别；
- 主体在 1.82:1 卡片裁切和移动端缩略图中仍安全；
- 至少提供三套有明显差异的配色方向，除非用户已经指定了配色；
- 没有把科技绿蓝、某种画风或某组色值误写成全站固定规则；
- 负面提示词没有误伤用户明确要求的颜色、文字或主体；
- 没有凭空加入品牌 Logo、产品界面细节或文章中未出现的事实。
