# 2026-10-26 第二轮健康报告对应优化

范围仅为当前 AICookCode 项目。报告中的其他四个站点不在此仓库中。本轮保留页面结构，不恢复已移除的“从一个具体任务开始”模块。

## 报告基线

报告对首页、`/articles/ui-assets-skill/` 和 `/topics/ai/` 各做了三轮 PSI：手机 LCP 中位数分别为 22.2、28.2、14.4 秒。它们是报告中旧部署的实验室结果，不是本轮修改后的测量。报告已确认基础抓取信号正常，本轮不更改 canonical、robots 或旧标签的退役策略。

## 本轮实现

- `integrations/optimize-images.mjs` 在 Astro 完成静态构建后解析实际 HTML，统一处理组件与 Markdown 的本地图片，自动生成 320 / 640 / 960 / 1440px 的 WebP 候选，并补充 `srcset`、`sizes`、真实宽高和异步解码。小图不放大；品牌图使用 180 / 240 / 480 / 720px。
- 首页精选图、专题与文章列表的首张封面、正文第一张图片优先加载，后续图片懒加载。原图片的全部像素内容保留，卡片仍由原 CSS 决定展示裁切方式。
- 原图继续在原 URL 提供，供历史链接、下载和社交分享使用。GIF 动画、SVG 和公众号二维码不重新压缩；二维码补齐真实尺寸并延迟加载。生成文件使用内容和处理版本的哈希命名，复用现有 `/_astro/*` 长缓存规则。
- 非自动播放视频改为 `preload="none"`，点击后才下载视频；海报改为压缩后的 WebP。视频源、播放控件和下载链接保留。
- 移除 Google Fonts 的远程 CSS 导入，改用系统字体；浅色主题次要文字加深，并给精选图片上的徽标添加深色实底。
- 新增 `site_search` 事件，在结果显示且输入稳定 600ms 后上报结果数量与输入长度；不发送搜索词，关闭弹窗取消待发送事件。沿用生产域限制和浏览器退出设置。

构建后的图片才是部署产物。`npm run dev` 仍使用原始图片；验证压缩应使用 `npm run build` 后的 `npm run preview`。

## 上线后必须复测

本轮没有对新部署运行 PSI，也未确认真实用户 Core Web Vitals 或 GA4 报表。上线后按以下步骤完成闭环：

1. 对 `/`、`/articles/ui-assets-skill/`、`/topics/ai/` 分别做三轮独立 PSI 分析，每轮检查手机与桌面，保留报告链接、日期、LCP、CLS、TBT 和失败原因；有效样本不足时补测，不将失败当作 0 分。
2. 手机 Network 中确认图片请求来自带哈希的 `/_astro/*.webp`，宽屏或高像素密度下能选择更大候选；确认没有 Google Fonts 请求。原图链接单独访问仍应成功，正文动画与二维码正常。
3. 在 GA4 DebugView 或实时报告核对 `site_search`、`article_read`、`project_visit`。一次稳定搜索应有一次 `site_search`，参数只包含数量、长度和公共页面路径。自访前后按 `docs/SEO.md` 设置统计退出。
4. 关键事件标记、GSC 关联和重点 URL 的重新抓取仍需在 Google 后台完成。报告的 reCAPTCHA 失败不是网站页面代码中的故障。
