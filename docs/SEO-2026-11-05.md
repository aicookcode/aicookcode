## 页面验证步骤

1. 在项目目录运行 `npm run build`、`npm run preview -- --port 4325`，打开 `http://127.0.0.1:4325/topics/`。确认原四个分类仍可用，下方有 WorkBuddy、AI 数字人与配音、UI 素材三个专题；在手机宽度也检查文字和入口。
2. 分别打开 `/topics/workbuddy/`、`/topics/ai-avatar/`、`/topics/ui-assets/`。确认“从哪里开始”、有序教程和文章卡片可读且可点击；WorkBuddy 三篇、数字人三篇、UI 两篇；打开任意文章后在“继续按专题阅读”回到对应专题。
3. 打开 `/topics/ai/`，确认专题入口；打开 `/articles/` 和 `/articles/workbuddy-5-settings/`，查看源代码确认新 title、description、唯一自引用 canonical 和 `index,follow`。关闭 JavaScript 后依然能读取正文和点击链接。
4. 打开 `/sitemap-index.xml` → `/sitemap-0.xml`，确认三个专题只出现各自的规范尾斜杠地址，且没有 `/tags/`、404、搜索 JSON 或 RSS。`/robots.txt` 保持 Allow 和正确 Sitemap 地址。
5. 发布后再次检查上面所有路径的真实 HTTP 状态与 canonical。对旧 `/tags/` 按此前记录抽查真实 404 与 noindex；不要统一跳转首页。若 GSC 导出的是其他六个 URL，则单独核对新旧内容关系，只有实质对应的页面才建立单跳 301。
6. GA4 只在 `aicookcode.com` 收集，本地和预览无事件是预期行为。发布后在测试浏览器打开 `https://aicookcode.com/?analytics=on`，借助 Google Analytics Debugger / GA4 DebugView 检查：阅读前台 60 秒且到正文 75% → `article_read`；RSS → `rss_subscribe_click`；邮箱/X/Telegram → `contact_click`；GitHub 仓库 → `project_visit`；普通外链 → `outbound_click`；文章视频备用下载链接 → `asset_download_click`。下载事件表示点击意向，不表示下载完成；不重复发送 GA4 自动增强型衡量的 `file_download`。
7. 核对事件参数无邮箱、搜索词、查询串和任意外链路径。测试后关闭调试，并打开 `/?analytics=off` 恢复本浏览器自访排除。

## 报告问题的处理边界与后续

- **42 个“已发现但未编入索引”**：当前源码会静态输出可见正文、标题、链接和自引用 canonical，未发现给这些文章统一 noindex 或 robots 阻挡。全站产物已验证，但没有报告的 URL 清单和线上响应证据，不能声称已解决 Google 的索引决策。导出 42 个 URL 后对照现有 Sitemap、URL 检查实时测试、Google 选择的 canonical 和内容质量逐项处理。
- **6 个 404 / 3 个重定向**：此前 `docs/SEO.md` 明确记录六个已退役标签没有等价内容，站内链接与 Sitemap 已移除。保持正常域名统一与 `/favicon.svg` 单跳兼容重定向。没有新的 3 个重定向 URL 证据，不删除所有正常重定向。
- **2api 查询主题**：用户补充的该查询仅有 18 次展示，不能据此认定为全站主要搜索主题。当前可发布文章中没有 2api 内容。本轮不凭这个小样本创建薄专题，也不删除未知旧内容；先从 GSC 导出对应着陆 URL，结合全站查询与页面表现判断。
- **GA4 关键事件**：前端只发送事件。仍需在正确 GA4 属性中将用户选定的 `article_read`、`rss_subscribe_click`、`contact_click`、`outbound_click`、`asset_download_click` 标记为关键事件；建议区分有效阅读与联系等业务意向，不将所有浏览当作成交。联系、订阅、下载点击不能冒充真实完成。没有 GA4 管理权限操作，故不报告“关键事件已设置”。
- **收录与 CTR**：部署后用 GSC 对新专题和高展示文章按需检查索引，再持续记录同口径点击、展示、CTR 与排名；代码改动不保证收录或点击率提升。
